🌐 How to Make Your App Live Without a Static IP

Normally, running a live web server on a custom domain requires purchasing a paid Static Public IP Address from your Internet Service Provider (ISP). With a standard Dynamic IP (common for home and office internet), your IP address changes periodically, which causes standard DNS records to break.

✅ The Free & Secure Solution: Cloudflare Tunnel

We use Cloudflare Tunnel (cloudflared) to connect your Ubuntu server directly to your custom domain without needing a static IP:

  • No Static IP Required: Your server opens a secure outbound encrypted connection to Cloudflare. Whenever your ISP changes your IP address, Cloudflare Tunnel remains connected automatically with zero downtime.
  • No Router Port Forwarding Required: Works effortlessly even behind strict firewalls and CGNAT (Carrier-Grade NAT).
  • Free Automatic SSL (HTTPS): Cloudflare automatically provisions and renews valid SSL certificates for your custom domain.
  • DDoS Protection & Hidden IP: Your actual home/office IP is hidden from the public internet, protecting your server against cyberattacks.

🛠️ Phase 1: Server Preparation & System Installation

1.1 Update System Packages

Open your terminal on the Ubuntu server and execute:

Terminal — Ubuntu Server
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl git build-essential ca-certificates rclone ufw jq lsof

1.2 Install Docker Engine & Docker Compose

Terminal — Ubuntu Server
# Install Docker and Docker Compose v2
sudo apt install -y docker.io docker-compose-v2

# Start Docker daemon and enable boot autostart
sudo systemctl enable --now docker

# Add current user to docker group (removes need for sudo)
sudo usermod -aG docker $USER

# Apply group permissions to current session
newgrp docker
ℹ️ Verify Docker Installation

Run docker --version and docker compose version. You should see Docker version 24+ and Docker Compose v2.x.

1.3 Install Node.js 20 LTS, PNPM, and PM2

Terminal — Ubuntu Server
# Add NodeSource Node.js 20 LTS repository
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -

# Install Node.js
sudo apt install -y nodejs

# Verify Node.js version (Must output v20.x.x)
node -v
npm -v

# Install PNPM (Package Manager) and PM2 (Process Manager) globally
sudo npm install -g pnpm pm2

1.4 Configure Server Firewall (UFW)

Terminal — Ubuntu Server
# Allow SSH access
sudo ufw allow 22/tcp

# Allow HTTP and HTTPS web traffic
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp

# Enable firewall
sudo ufw --force enable
sudo ufw status

⚡ Phase 6: PM2 Process Management & Service Autostart

PM2 keeps your Node.js applications running 24/7, handles automatic crash restarts, and restores services whenever the server reboots.

6.1 Create PM2 Configuration (ecosystem.config.js)

Create the file ~/pms/ecosystem.config.js with the following dynamic configuration:

~/pms/ecosystem.config.js
const path = require('path');
const rootDir = __dirname;

module.exports = {
  apps: [
    {
      name: "pms-api",
      script: "apps/api/dist/main.js",
      cwd: rootDir,
      instances: 1,
      exec_mode: "fork",
      env: {
        NODE_ENV: "production",
        PORT: 3001,
        HOST: "0.0.0.0",
      },
      max_memory_restart: "500M"
    },
    {
      name: "pms-worker",
      script: "apps/worker/dist/main.js",
      cwd: rootDir,
      instances: 1,
      exec_mode: "fork",
      env: {
        NODE_ENV: "production",
      },
      max_memory_restart: "400M"
    },
    {
      name: "pms-web",
      script: "node_modules/next/dist/bin/next",
      args: "start apps/web -p 3002",
      cwd: rootDir,
      instances: 1,
      exec_mode: "fork",
      env: {
        NODE_ENV: "production",
        PORT: 3002
      },
      max_memory_restart: "600M"
    }
  ]
};

6.2 Start PM2 Services & Verify Status

Terminal
cd ~/pms
pm2 start ecosystem.config.js
pm2 status

6.3 Enable Auto-Start on Server Reboot

Terminal
# 1. Save active PM2 app list
pm2 save

# 2. Generate and enable systemd startup hook
pm2 startup

Important: Copy and execute the exact command string displayed by pm2 startup in your terminal.

🌐 Phase 7: Connect Custom Domain via Cloudflare Tunnel (Dynamic IP Support)

Follow these exact steps to make your application live on your custom domain without a static IP address or router port forwarding.

Step 7.1: Add Your Domain to Cloudflare (Free)

  1. Sign up for a free account at Cloudflare Dashboard.
  2. Click Add a site, enter your purchased domain name (e.g., yourdomain.com), and select the Free plan.
  3. Cloudflare will assign you 2 Cloudflare Nameservers (e.g., ada.ns.cloudflare.com and bob.ns.cloudflare.com).

Step 7.2: Update Nameservers at Your Domain Registrar

  1. Log into the account where you bought your domain (Namecheap, GoDaddy, Hostinger, Porkbun, Google Domains, etc.).
  2. Navigate to DNS / Nameservers settings for yourdomain.com.
  3. Switch the Nameserver setting to Custom DNS / Custom Nameservers.
  4. Paste the 2 Cloudflare Nameservers and click Save. (DNS propagation usually takes 5–15 minutes).

Step 7.3: Create Cloudflare Tunnel in Zero Trust

  1. In your Cloudflare Dashboard, click Zero Trust in the left sidebar.
  2. Navigate to Networks → Tunnels → click Create a Tunnel.
  3. Select Cloudflared as connector → Click Next.
  4. Name your tunnel: pms-ubuntu-server → Click Save tunnel.

Step 7.4: Install & Run cloudflared Daemon on Ubuntu Server

Under Choose an environment, select Debian / Ubuntu. Copy and execute:

Terminal
# Download cloudflared Debian package
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb

# Install package
sudo dpkg -i cloudflared.deb

# Install and run cloudflared service with your unique tunnel token
sudo cloudflared service install <PASTE_YOUR_CLOUDFLARED_TOKEN_FROM_DASHBOARD>

# Verify service is active and connected
sudo systemctl status cloudflared

Step 7.5: Map Public Hostnames in Cloudflare Tunnel Dashboard

In the Cloudflare Tunnel Public Hostname tab, click Add a public hostname for each of the following routes:

Subdomain Domain Type URL / Target Description
www yourdomain.com HTTP localhost:3002 Next.js Web Frontend App
(Leave Blank / @) yourdomain.com HTTP localhost:3002 Root Domain Redirect
api yourdomain.com HTTP localhost:3001 NestJS Backend REST API
storage (Optional) yourdomain.com HTTP localhost:9000 MinIO S3 File Storage
🎉 You're Live!

Once saved, visit https://www.yourdomain.com. Your app will load securely over HTTPS with Cloudflare shielding your dynamic IP address!

☁️ Phase 8: Automated Nightly Backups to Google Drive

Protect your database against accidental deletion or hardware failures by scheduling automated nightly backups to Google Drive with 7-day rolling retention.

8.1 Connect Google Drive via rclone

Terminal
rclone config
  1. Type n for New remote and name it gdrive.
  2. Select Google Drive from the list of cloud storage providers.
  3. Leave Client ID / Secret blank (press Enter).
  4. Access Scope: Select 1 (Full access).
  5. Auto-config: Select N (for remote headless CLI), open the authorization link in your browser, sign in, and paste the verification code.

8.2 Create Backup Script (~/pms/backup-to-gdrive.sh)

~/pms/backup-to-gdrive.sh
#!/bin/bash
set -e

BACKUP_DIR="$HOME/pms-backups"
TIMESTAMP=$(date +"%Y-%m-%d_%H-%M-%S")
DB_CONTAINER="pms_postgres"
DB_USER="pms"
DB_NAME="pms"
GDRIVE_REMOTE="gdrive:PMS_Backups"
RETENTION_DAYS=7

echo "[$(date)] 🚀 Starting Daily Database Backup..."

mkdir -p "$BACKUP_DIR"
BACKUP_FILE="$BACKUP_DIR/pms_backup_$TIMESTAMP.sql.gz"

echo "📦 Dumping database from container '$DB_CONTAINER'..."
docker exec -t "$DB_CONTAINER" pg_dump -U "$DB_USER" "$DB_NAME" | gzip > "$BACKUP_FILE"

echo "☁️ Uploading to Google Drive ($GDRIVE_REMOTE)..."
rclone copy "$BACKUP_FILE" "$GDRIVE_REMOTE"

echo "🧹 Pruning Google Drive backups older than $RETENTION_DAYS days..."
rclone delete --min-age "${RETENTION_DAYS}d" "$GDRIVE_REMOTE"

find "$BACKUP_DIR" -type f -name "*.sql.gz" -mtime +$RETENTION_DAYS -exec rm -f {} \;
echo "[$(date)] 🎉 Nightly backup finished successfully!"
Terminal — Make Executable
chmod +x ~/pms/backup-to-gdrive.sh
~/pms/backup-to-gdrive.sh

8.3 Schedule Nightly Cron Job (@ 2:00 AM)

Terminal
crontab -e

# Add this line to the bottom of your crontab:
0 2 * * * $HOME/pms/backup-to-gdrive.sh >> $HOME/pms/backup.log 2>&1

🔄 Phase 9: 1-Click Code Update Script

Whenever you push new code changes from your development laptop to GitHub, use this script to pull, build, and restart production services in a single command.

9.1 Create Update Script (~/pms/update-live.sh)

~/pms/update-live.sh
#!/bin/bash
set -e

echo "🚀 Starting 1-Click Production Deployment"
cd "$HOME/pms"

echo "📥 1. Pulling latest code from Git..."
git pull origin main

echo "📦 2. Installing dependencies..."
pnpm install

echo "🗄️ 3. Running Prisma migrations..."
pnpm --filter @pms/api prisma:migrate

echo "🏗️ 4. Building Backend API, Worker & Web App..."
pnpm --filter @pms/api build
pnpm --filter @pms/worker build
pnpm --filter @pms/web build

echo "🔄 5. Restarting PM2 process manager..."
pm2 restart ecosystem.config.js

echo "✅ Production Deployment Complete!"
Terminal
chmod +x ~/pms/update-live.sh

# Run whenever you want to update production:
cd ~/pms && ./update-live.sh

Common Diagnostic Tips

  • Port 3001 already in use: Find process with sudo lsof -i :3001 and kill it with sudo kill -9 <PID>, then run pm2 restart pms-api.
  • Database connection refused: Ensure Docker containers are running using docker compose restart postgres.
  • CORS errors on web frontend: Verify your custom domain is listed in CORS_ORIGIN inside ~/pms/apps/api/.env.
